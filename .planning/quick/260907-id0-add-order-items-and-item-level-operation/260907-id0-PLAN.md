<objective>
Add a first-party `public.order_items` table (FK to `public.orders`, created by issue #9) and
populate it on every checkout with **server-derived** name and price snapshots looked up from
Square's Catalog *before* any Square order call — so operations can answer "what is in this
order" from Supabase alone, at the line-item level, without trusting the client or depending on
Square order-creation timing (GitHub issue #3).

Also delete the dead second line-item payload shape: `app/api/checkout/route.ts` carries an
`orderItems` Zod field and a `(parsed.data.orderItems ?? cart)` fallback that nothing in the
repo ever populates. `parsed.data.cart` is and always was the real input.

Purpose: `orders.cart_snapshot` is raw client JSON holding only `variationId`/`quantity` — it
cannot produce a pack list, a production count, or a per-item revenue report. `order_items`
turns each checkout into queryable, priced, human-readable lines that survive Square outages.

Output: One additive migration, matching hand-edited generated types, a reworked persistence
path in the checkout route, and Vitest coverage for the new flow.
</objective>

  `createOrder` response per issue #9. CONTEXT explicitly accepts the two Catalog-derived name
