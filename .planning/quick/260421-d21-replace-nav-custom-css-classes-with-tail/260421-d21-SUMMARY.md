## What Changed

### tailwind.config.ts
Added `screens: { nav: "960px" }` under `theme.extend` — registers the `nav:` responsive variant without overriding default Tailwind breakpoints (sm/md/lg/xl/2xl).

### components/NavBar.tsx
Replaced all 5 custom-class usages with Tailwind `nav:` utilities:
- Desktop `<nav>`: `nav-desktop` → `hidden nav:flex nav:flex-row nav:items-center nav:gap-8`
- Order Now `<Link>`: `nav-order-btn` → `hidden nav:inline-flex`
- Hamburger `<button>`: `nav-mobile-only inline-flex` → `inline-flex nav:hidden`
- Overlay `<div>`: `nav-mobile-only` → `nav:hidden`
- Drawer `<aside>`: `nav-mobile-only` → `nav:hidden`

### app/globals.css
Removed the entire `/* Nav responsive helpers */` block (24 lines) including the `.nav-desktop`, `.nav-mobile-only`, `.nav-order-btn` rules and the `@media (min-width: 960px)` block.

## Why This Fixes the Issue

The old custom CSS declared display rules _after_ `@tailwind utilities` in the stylesheet, creating cascade ambiguity where stale display values could persist through window resize. Tailwind's responsive variants (`nav:`) emit utilities in the same cascade layer as all other utilities, so the breakpoint toggle is handled natively and reliably on resize.
