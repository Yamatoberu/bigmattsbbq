<objective>
Replace the fragile custom CSS responsive helpers (`.nav-desktop`, `.nav-mobile-only`, `.nav-order-btn`) used by the NavBar with a Tailwind-native approach: register a custom `nav` screen at 960px in `tailwind.config.ts`, convert NavBar markup to use `nav:` responsive utilities, and delete the obsolete CSS block from `app/globals.css`.

Purpose: The current custom classes are declared in `app/globals.css` before Tailwind utilities are emitted, which creates cascade/specificity ambiguity. After resize, stale display rules can win over expected behavior. Using Tailwind's responsive variants puts the breakpoint logic in the same cascade layer as every other utility, matches the project convention (no custom CSS helper classes where Tailwind suffices), and keeps the 960px breakpoint decision (from quick-260421-cs6) authoritative.

Output: A NavBar that responds cleanly to window resize across the 960px boundary using only Tailwind utilities, with the custom CSS block removed.
</objective>
