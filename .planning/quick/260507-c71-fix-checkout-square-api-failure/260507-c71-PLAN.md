<objective>
Fix the checkout Square API failure by (a) making logError surface the SquareError body and status so we can actually see why Square rejected the request, and (b) removing the bogus duplicate bundleVariationId line item that the checkout route currently appends to every order.

Purpose:
- The current logError throws away SquareError.body, which is where Square puts the actual rejection reason (errors[].code, detail, field). Adding it makes future failures debuggable in one log line.
- The checkout route appends a second line item with `catalog_object_id: pkg.bundleVariationId` and `base_price_money: { amount: 0, currency: "USD" }` AFTER already mapping the cart. The cart already contains the correct items: either the bundle variation (when it exists in Square) or resolved individual items (when it doesn't). Appending `bundleVariationId` again either duplicates the line item or — in sandbox where the production bundle variation doesn't exist — sends Square a `catalog_object_id` it can't resolve, which is the most likely cause of the current failure.

Output:
- `lib/logger.ts` updated to detect `SquareError` and include `status` + `body` in the structured log.
- `app/api/checkout/route.ts` updated so `line_items` is just `cart.map(...)` — no PACKAGES lookup, no bundleVariationId append, no zero-priced phantom line.
</objective>

From lib/square.ts (the error type that needs special handling in logError):
```typescript
export class SquareError extends Error {
  status: number;
  body: unknown;

  constructor(message: string, status: number, body: unknown) {
    super(message);
    this.status = status;
    this.body = body;
  }
}
```

Current lib/logger.ts (the function being extended):
```typescript
export function logError(message: string, error: unknown, requestId?: string) {
  const normalized = error instanceof Error
    ? { name: error.name, message: error.message, stack: error.stack }
    : { error };
  console.error({ requestId, message, ...normalized });
}
```

Current checkout createOrder line_items shape (the buggy code being removed):
```typescript
line_items: [
  ...cart.map((item) => ({
    quantity: item.quantity.toString(),
    catalog_object_id: item.variationId
  })),
  ...((() => {
    const pkg = parsed.data.packageId
      ? PACKAGES.find((p) => p.id === parsed.data.packageId)
      : undefined;
    return pkg?.bundleVariationId
      ? [{ quantity: "1", catalog_object_id: pkg.bundleVariationId, base_price_money: { amount: 0, currency: "USD" } }]
      : [];
  })())
]
```

Target line_items shape (what it should become):
```typescript
line_items: cart.map((item) => ({
  quantity: item.quantity.toString(),
  catalog_object_id: item.variationId
}))
```

Note: the `PACKAGES` import in app/api/checkout/route.ts becomes unused after this fix and must be removed (TypeScript strict mode + lint will flag it otherwise — see CLAUDE.md "TypeScript strict: true").
