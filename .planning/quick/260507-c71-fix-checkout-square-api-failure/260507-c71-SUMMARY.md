# Phase quick-260507-c71 Plan 01: Fix Checkout Square API Failure Summary

**One-liner:** Fixed two Square API failures: silent SquareError logs (no status/body) and a duplicate bundleVariationId phantom line item with `base_price_money: 0` appended to every checkout order.

## What Was Fixed

### Root Cause 1: Silent SquareError logging

`logError` in `lib/logger.ts` used a single `error instanceof Error` branch that normalized all errors to `{ name, message, stack }`. When Square returned a rejection, `SquareError.body` (containing Square's actual `errors[].code` and `detail`) and `SquareError.status` were silently discarded. The developer could only see "Checkout failed" with no Square error detail.

**Fix:** Added `instanceof SquareError` check as the first branch in `logError`. SquareErrors now emit `{ name, errorMessage, stack, status, body }` — all the detail needed to identify the Square rejection code without re-running the request.

**Note:** The `message` key in the log object is reserved for the outer `logError` message parameter (the call-site label). The error's own message is under `errorMessage` to avoid collision.

### Root Cause 2: Duplicate bundleVariationId line item

`app/api/checkout/route.ts` built `line_items` by first mapping `cart` items, then appending a second entry with `catalog_object_id: pkg.bundleVariationId` and `base_price_money: { amount: 0, currency: "USD" }`. This phantom line was the most likely cause of Square rejections in sandbox because:
- The `bundleVariationId` is a production Square catalog object ID that doesn't exist in the sandbox catalog
- Sending Square a `catalog_object_id` it can't resolve causes a 422 or similar rejection
- Even in production, this duplicated the bundle variation that the cart already contained

**Fix:** Replaced the spread+IIFE construction with a clean `cart.map(...)`. The `PACKAGES` import was removed as it became unused. Cart items are sent verbatim to Square exactly as the client provided them.

### Bonus fix: SquareError.name

Added `this.name = "SquareError"` to the `SquareError` constructor in `lib/square.ts`. Custom Error subclasses that don't set `this.name` inherit `"Error"` as their name, making logs and stack traces misleading. This is a standard convention fix.
