# Quick Task 260917-s2u: Capture full live Supabase schema drift

## Context

While rebuilding a `bigmattsbbq-test` Supabase project as a safe e2e/dev environment (issue #14),
comparison of this repo's `supabase/migrations/` (9 files, 0001-0009) against production's own
Supabase-tracked migration history (`supabase_migrations.schema_migrations`, 12 entries) surfaced
three tracked-on-prod-but-missing-from-repo migrations, plus two entire schemas that were created
directly against production (via SQL editor or similar) and were never captured in Supabase's own
migration tracking at all, let alone in git:

| Source | Content | Repo status |
|---|---|---|
| prod-tracked, 20260724212041 `menu_costing_schema` | `menu_costing` schema: types, 12 tables, 1 view, 2 functions | missing from repo |
| prod-tracked, 20260724213129 `add_vendor_shorthand` | `alter table menu_costing.vendors add column shorthand` | missing from repo |

| untracked anywhere | `sca` schema: 7 tables, FKs, indexes, 2 trigger functions, 6 triggers, 8 RLS policies | missing from repo |
| untracked anywhere | `production` schema: 4 tables (equipment, production_runs, products, production_cooks), FKs, indexes | missing from repo |

User decision (2026-09-17): capture **all** of the above into `supabase/migrations/`, in the interest
of the repo becoming the true source of truth for everything live in this Supabase project — not just
the parts that belong to this specific Next.js app. `menu_costing` is unrelated to this app's code
(confirmed via repo-wide grep, zero hits) but is real, tracked history in the same Supabase project.
`production` is unreferenced in app code today but its shape maps to open issues #7 and #12
(admin/fulfillment features not yet built).

All SQL below was retrieved directly from two authoritative sources and is to be transcribed
**verbatim, byte-for-byte** — do not reformat, regenerate, paraphrase, or "improve" it:
1. Production's own `supabase_migrations.schema_migrations.statements` column (for the 3
   prod-tracked migrations) — this is the exact SQL Supabase itself applied to prod.
2. `bigmattsbbq-test`'s clone migrations (for `sca` and `production`, since these were never
   migration-tracked on prod) — Supabase's structural-clone tool introspected the live prod
