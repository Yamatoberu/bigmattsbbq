## Overview

Complete website refresh for Big Matt's BBQ: transformed a hardcoded Next.js storefront into a fully database-driven frozen BBQ drop platform. Customers can preorder frozen BBQ products from a live drop without overselling — capacity is enforced atomically, pickup options are configurable per drop, and all orders flow into Supabase for tracking.

New in v1.0: Supabase persistence layer (drops, orders, mailing list, email logs), atomic slot reservation before Square API calls, deterministic idempotency keys, mailing list with unsubscribe and broadcast capability via Resend, site-wide navigation, and static catering/about/contact pages.

## Milestone Summary

### Key Decisions

| Decision | Rationale | Outcome |
|----------|-----------|---------|
| Keep Square invoices | Already working; PRD non-goal is online payment, not invoicing | ✓ Good |
| Supabase for new data | Structured drops/orders/mailing list without overloading Square | ✓ Good |
| Square stays for inventory | Atomic inventory handled by Square; avoid dual-source complexity | ✓ Good |
| Resend for email | Simple API for transactional + mailing list | ✓ Good |
| Database-driven drops, no admin UI | Flexibility without redeploy; admin dashboard deferred to v2 | ✓ Good |
| MAIL-01 deferred (D-10) | Square invoice email covers MVP confirmation; Resend confirmation is post-MVP | ✓ Good |
| Slot reservation before Square calls | Atomicity guarantee; capacity never oversold | ✓ Good |
| Deterministic idempotency (SHA-256) | Prevents duplicate orders on retries without UUID randomness | ✓ Good |
| Unsubscribe via signed JWT (jose) | Stateless, no DB lookup needed for token verification | ✓ Good |
| Single migration file | All DDL, RLS, functions in one file — simpler to inspect and replay | ✓ Good |
