## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Public internet → /api/test-seed | Any unauthenticated caller can hit this route over HTTPS |
| Route handler → Supabase | Service-role Supabase client reads drop + pickup capacity rows |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06-01 | Information Disclosure | GET /api/test-seed in production | mitigate | Add `env.environment !== "sandbox"` short-circuit returning 404 BEFORE any Supabase call. Mirrors the proven guard in `app/api/dev/set-inventory/route.ts`. |
| T-06-02 | Information Disclosure | 404 response body | accept | Returning generic `{ error: "Not found." }` (no request id) is intentional — matches `set-inventory` and avoids confirming route existence to scanners. |
| T-06-03 | Denial of Service | Public GET hammered in production | mitigate | Guard returns 404 before allocating a Supabase client or running any query, so the route becomes a cheap constant-time response in production. |
| T-06-04 | Tampering | Env var `SQUARE_ENV` flipped to "sandbox" in production | accept | Out of scope for this fix — env management is operator responsibility. The guard correctly enforces the contract `SQUARE_ENV` advertises. |
| T-06-05 | Repudiation | No audit log of production calls hitting the guarded route | accept | Low value; Vercel access logs already capture requests. Adding structured logging is deferred. |
</threat_model>
