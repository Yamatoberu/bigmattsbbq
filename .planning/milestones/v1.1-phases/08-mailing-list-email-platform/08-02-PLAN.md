<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| broadcast props -> rendered HTML | `subject` (string from authenticated admin) and `dropId` (optional) are interpolated into JSX text — React Email + JSX auto-escape these |
| `{{{RESEND_UNSUBSCRIBE_URL}}}` placeholder -> Resend substitution | Resend replaces the literal at send-time with a per-recipient signed URL |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-08-06 | Tampering / XSS | `subject` prop interpolated into `<Text>{subject}</Text>` and `<Preview>{subject}</Preview>` | mitigate | JSX/React auto-escape string children — no `dangerouslySetInnerHTML`. Schema validation in Plan 03 (Zod `z.string().min(1).max(200)`) caps length and ensures string type. Caller is bearer-authenticated admin. |
| T-08-07 | Tampering | `dropId` prop interpolated into `orderUrl` query string | mitigate | `encodeURIComponent(dropId)` applied before string concat. Zod `.string().optional()` validates type at the route boundary (Plan 03). |
| T-08-08 | Information Disclosure | `{{{RESEND_UNSUBSCRIBE_URL}}}` could be HTML-escaped by `render()`, breaking native unsubscribe | mitigate | Per RESEARCH.md Pitfall 3: placed inside React Email's `<Link href="...">` (passes href through unescaped per official docs). Plan 03 verification step asserts the literal string survives `render()` in the rendered HTML. |
| T-08-09 | Denial of Service | Excessively large `subject` would bloat email | mitigate | Schema in Plan 03 already caps `subject` at 200 chars. |
| T-08-10 | Information Disclosure | No PII in template (no recipient name, email, order details) | accept | Drop-notification template is generic/promotional. PII-bearing emails (e.g., MAIL-01 confirmation) are explicitly out of scope. |

Note: This plan introduces no new auth/access-control surface. The component is pure JSX; access controls live on the broadcast route in Plan 03.
</threat_model>
