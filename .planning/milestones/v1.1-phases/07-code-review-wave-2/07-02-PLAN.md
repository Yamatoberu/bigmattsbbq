CHANGE 2 — Wrap the six callbacks in `useCallback` and complete the `useMemo` dep array.

REPLACE lines 45-78 (the six callback declarations plus the existing `useMemo`) with the block below. Indentation is 2-space, matching `.editorconfig`. The block lives inside `CartProvider`, two levels deep, so each line starts with 2 spaces:

```
  const addItem = useCallback((item: CartItem) => {
    setItems((prev) => mergeCartItems(prev, [item]));
  }, []);

  const addItems = useCallback((newItems: CartItem[]) => {
    setItems((prev) => mergeCartItems(prev, newItems));
  }, []);

  const setQuantity = useCallback((variationId: string, quantity: number) => {
    setItems((prev) => {
      if (quantity <= 0) {
        return prev.filter((item) => item.variationId !== variationId);
      }
      return prev.map((item) =>
        item.variationId === variationId ? { ...item, quantity } : item
      );
    });
  }, []);

  const removeItem = useCallback((variationId: string) => {
    setItems((prev) => prev.filter((item) => item.variationId !== variationId));
  }, []);

  const setPackage = useCallback((id: string | undefined) => {
    setSelectedPackageId(id);
  }, []);

  const clear = useCallback(() => {
    setItems([]);
    setSelectedPackageId(undefined);
  }, []);

  const value = useMemo(
    () => ({ items, isReady, selectedPackageId, addItem, addItems, setQuantity, removeItem, setPackage, clear }),
    [items, isReady, selectedPackageId, addItem, addItems, setQuantity, removeItem, setPackage, clear]
  );
```

Why each `useCallback` has empty deps `[]`:
- `setItems` and `setSelectedPackageId` are `useState` setters — React guarantees stable identity across renders, so they don't need to be listed.
- `mergeCartItems` is an imported pure function (already imported at top of file from `../../lib/cart`) — module-scope binding, never captured from closure.
- All callbacks use the functional updater form `setItems((prev) => ...)`, so they never read `items` from the closure. They read `prev`, which React supplies fresh on each call.
- `setPackage` body becomes a block `{ setSelectedPackageId(id); }` instead of the previous expression form `=> setSelectedPackageId(id)`. This is a stylistic alignment with the other callbacks; behavior is identical.

Why the `useMemo` dep array now lists nine entries: each callback is now a stable identity (same reference across renders), so listing them in the dep array does not cause extra re-memos — the `value` object still only changes when `items`, `isReady`, or `selectedPackageId` changes. This satisfies exhaustive-deps without the latent stale-closure risk.
