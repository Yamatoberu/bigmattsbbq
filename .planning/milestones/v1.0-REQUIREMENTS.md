# Requirements Archive: Big Matt's BBQ v1.0

**Archived:** 2026-04-22
**Milestone:** v1.0 — Website Refresh & Frozen Drops
**Core Value:** Customers can preorder frozen BBQ from a live drop without overselling — capacity is enforced, pickup is clear, and confirmation is immediate.

---

## v1 Requirements — Final Status

### Data Foundation

- [x] **DATA-01**: Supabase schema created with tables for drops, drop_pickup_options, orders, mailing_list, and email_logs
  - *Outcome: Satisfied — Phase 1, Plan 01. Single migration file, all 5 tables with RLS.*
- [x] **DATA-02**: Row-level security enabled on all Supabase tables from initial creation
  - *Outcome: Satisfied — Phase 1, Plan 01. RLS enabled with no anon policies; service role bypasses.*
- [x] **DATA-03**: Drops are managed in Supabase with configurable products, capacity, and pickup options per drop
  - *Outcome: Satisfied — Phase 2 + Phase 3 gap closure. `getActiveDrop()` and pickup options from DB.*
- [x] **DATA-04**: Each drop has a state (upcoming/active/closed) that controls ordering availability
  - *Outcome: Satisfied — Phase 2. Drop state checked before accepting orders.*
- [x] **DATA-05**: Drop pickup options (dates, locations, time windows) are stored in Supabase and replace hardcoded config
  - *Outcome: Satisfied — Phase 2. `getDropPickupOptions()` replaces `PICKUP_OPTIONS` config array.*

### Ordering & Checkout

- [x] **ORD-01**: Capacity reservation uses atomic Supabase slot reservation before Square API calls to prevent overselling
  - *Outcome: Satisfied — Phase 3 (wired) + Phase 4 (verified ordering). `reserve_pickup_slot` RPC called before Square try block.*
- [x] **ORD-02**: Order record is saved to Supabase with a JSONB cart snapshot at time of purchase
  - *Outcome: Satisfied — Phase 4, Plan 02. `orders` insert after `publishInvoice` succeeds; fire-and-forget.*
- [x] **ORD-03**: Idempotency keys are deterministic (derived from order data) to prevent duplicate orders
  - *Outcome: Satisfied — Phase 4, Plan 01. SHA-256 over sorted inputs, 45-char hex slice. 6/6 tests pass.*
- [x] **ORD-04**: Checkout validates that the drop is active before accepting orders
  - *Outcome: Satisfied — Phase 2. Drop state validation in checkout route.*
- [x] **ORD-05**: Products display sold-out indicators in real-time when capacity is reached
  - *Outcome: Satisfied — Phase 2 + Phase 3. Supabase capacity drives sold-out display.*

## Out of Scope (Final)

| Feature | Reason |
|---------|--------|
| Online payment processing | Payment collected at pickup; Square invoices for tracking only |
| Shipping frozen products | Pickup-only model for freshness and logistics |
| Subscriptions / recurring billing | Not part of the drop model |
| Complex catering scheduling | Static page with email CTA is sufficient for MVP |
| Accounting system integrations | Not needed for MVP operations |
| Admin dashboard | Manage drops directly in Supabase for MVP (deferred to v2) |
| Branded Resend confirmation email (MAIL-01) | Square invoice email covers MVP; deferred to v1.1 via D-10 |
