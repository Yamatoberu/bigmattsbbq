## Integration Issues

### GAP-01 (Low) — Type-only gap, no runtime break
**Affected:** ORD-02

`lib/types.ts` `CheckoutRequestBody.cart` is typed as `CartItem[]`. `CartItem = { variationId: string; quantity: number }`. The `productName` and `priceCents` fields sent by `CheckoutClient` and accepted by the Zod schema are absent from this TypeScript type. Runtime is unaffected (Zod governs the actual validator). Risk: a future caller constructing from the type alone omits `productName` → capacity reservation silently skips that item, and `priceCents` records as 0 in cart_snapshot.

**Fix:** Add `productName?: "pulled_pork" | "brisket"` and `priceCents?: number` to `CartItem` or create a `CheckoutCartItem` extension type.

### INT-02 (Medium) — Fragile productName mapping
**Affected:** ORD-05, DATA-03

See prior audit. Still open. `productNameMap` in `CheckoutClient` slugifies Square catalog names against `"pulled_pork"` / `"brisket"` literals. If Square item names change, `reserve_pickup_slot` is silently never called.

**Fix:** Add server-side logging when `aggregateByProduct` map is empty but cart contains non-sauce items (items with quantity > 0 but no productName).
