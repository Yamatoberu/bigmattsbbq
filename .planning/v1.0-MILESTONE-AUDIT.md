## Integration Issues

### INT-01 (Low): `aggregateByProduct` not used in production

`lib/cart.ts` lines 54–64 exports `aggregateByProduct`. However, `app/api/checkout/route.ts` lines 112–117 contains an inline duplicate of the same logic. The test at `tests/checkoutReservation.test.ts:61` imports and tests the `lib/cart.ts` version — not the production code path.

Both implementations are behaviorally identical today, so this is not a runtime defect. But tests do not cover the actual production logic path.

**Fix:** Import `aggregateByProduct` from `lib/cart.ts` in the route and remove the inline duplicate.

### INT-02 (Medium): Fragile `productName` mapping in CheckoutClient

`components/CheckoutClient.tsx` lines 52–53 slugify Square catalog item names and match against `"pulled_pork"` and `"brisket"` literals. If Square item names ever deviate (e.g. "Smoked Pulled Pork"), the `productNameMap` produces no entries, `totals` is empty in the route, `reserve_pickup_slot` is never called, and capacity counters are never incremented — silently re-opening the pre-Phase-3 overselling gap.

No server-side validation catches a checkout with meat items missing `productName`. The route skips the RPC loop without logging.

**Fix:** Add a server-side warning log when cart contains items with non-zero quantity but no `productName`, or validate against the known Square item names.
