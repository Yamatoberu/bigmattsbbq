## Critical Gap: reserve_pickup_slot Never Called

**Root cause:** Both partial requirements share a single root cause.

`reserve_pickup_slot` and `release_pickup_slot` RPCs are:
- Defined in `supabase/migrations/0001_foundation.sql` (Phase 1)
- Typed in `lib/database.types.ts`
- Intended to atomically increment/decrement capacity counters on `drops` and `drop_pickup_options`

But `POST /api/checkout` (`app/api/checkout/route.ts`) never calls either RPC after a successful Square invoice publication. The result:

| Column | Expected after order | Actual after order |
|--------|---------------------|-------------------|
| `drops.reserved_pulled_pork` | +N (quantity ordered) | 0 (unchanged) |
| `drops.reserved_brisket` | +N | 0 (unchanged) |
| `drop_pickup_options.reserved_*` | +N | 0 (unchanged) |

**Consequence chain:**
1. `fetchActiveDrop()` derives `soldOut.pulledPork = reserved >= capacity` — always false
2. `drop.soldOut` passed to `OrderLanding` — always {pulledPork: false, brisket: false}
3. `FrozenItemCard soldOut` prop — always false
4. `checkDropReady()` checks `reserved >= capacity` — always false (allows all orders)
5. Unlimited orders accepted regardless of capacity — **overselling is possible**

This directly contradicts the project's core value: *"Customers can preorder frozen BBQ from a live drop without overselling — capacity is enforced."*
