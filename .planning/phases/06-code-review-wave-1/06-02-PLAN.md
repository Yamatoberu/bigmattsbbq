**Step 1 — Add the helper at module scope.** Insert this function after the `checkoutSchema` declaration (around line 39) and BEFORE the `export async function POST` declaration:

```typescript
async function releaseReserved(
  supabase: ReturnType<typeof getSupabaseClient>,
  reserved: Array<{ productName: string; quantity: number }>,
  dropId: string,
  pickupOptionId: string,
  requestId: string
): Promise<void> {
  const results = await Promise.allSettled(
    reserved.map((r) =>
      supabase.rpc("release_pickup_slot", {
        p_drop_id: dropId,
        p_pickup_option_id: pickupOptionId,
        p_product_name: r.productName,
        p_quantity: r.quantity
      })
    )
  );
  for (const result of results) {
    if (result.status === "rejected") {
      logError("release_pickup_slot failed", result.reason, requestId);
    }
  }
}
```

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Public internet → POST /api/checkout | Cart payloads enter from the browser (already validated by Zod) |
| Checkout handler → Supabase RPC | Service-role calls to `reserve_pickup_slot` / `release_pickup_slot` |
| Checkout handler → Square API | Network calls that may partially succeed/fail |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06-06 | Tampering | Reserved-capacity rows in `drop_pickup_options` | mitigate | New helper releases ALL reserved slots even if one RPC rejects (was: sequential await stopped on first throw, leaving later slots stranded). `Promise.allSettled` guarantees every release attempt runs. |
| T-06-07 | Repudiation | Release RPC failures going unlogged | mitigate | Helper iterates `results` and calls `logError("release_pickup_slot failed", reason, requestId)` for each rejection. Ops can now correlate stranded capacity with `requestId`. |
| T-06-08 | Denial of Service | Stranded reservations blocking other customers from purchasing | mitigate | Same as T-06-06 — parallel allSettled prevents the "first failure poisons the rest" pattern that was silently leaking slots. |
| T-06-09 | Information Disclosure | `logError` includes RPC reason which may contain DB error text | accept | `logError` already writes to `console.error` only (no external sink). Same disclosure surface as the rest of the route. |
| T-06-10 | Elevation of Privilege | Helper called with arbitrary `dropId` / `pickupOptionId` from caller | mitigate | All call sites pass `parsed.data.dropId` / `parsed.data.pickupOptionId` — already Zod-validated as `z.string().uuid()` at the route entry. No new trust boundary introduced by the refactor. |
| T-06-11 | Spoofing | RPC executed with wrong `requestId` for tracing | accept | `requestId` is passed by reference from the route's request-scoped variable; no spoofing surface within process. |
</threat_model>
