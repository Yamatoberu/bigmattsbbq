<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Public visitor → `/sca/competitions/[id]` path segment | Arbitrary attacker-controlled string reaching server-side code |
| Supabase `sca` rows → rendered page | Operator-entered free text (`name`, `notes`, `organizer`, `city`) becomes page content |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-10-21 | Tampering | `[id]` route param | mitigate | `parseScaId(id)` runs before any query; `null` triggers `notFound()`. Non-numeric, negative, fractional, and oversized inputs never reach `.eq("id", ...)`. Unit-tested in Plan 10-04; asserted here by the two `curl` 404 checks. (ASVS V5.) |
| T-10-22 | Information Disclosure (IDOR) | `/sca/competitions/[id]` | accept | Every competition row is public SCA competition history for a single chef; there is no per-user ownership boundary this milestone (no auth by design, multi-chef deferred to PLAT-01). Id enumeration reveals nothing beyond what `/sca/competitions` already lists. Revisit at PLAT-01. |
| T-10-23 | Information Disclosure | catch blocks on both pages | mitigate | `logError()` server-side only; the visitor sees the locked generic string. Gated by `grep -c "error.message" == 0` on both files. |
| T-10-24 | Tampering (stored XSS) | competition `name` / `notes` / `organizer` rendering | mitigate | Rendered as JSX text; React escapes. No `dangerouslySetInnerHTML`, and no `href` is built from free-text fields — links use numeric ids only. |
| T-10-25 | Denial of Service | competition with zero cooks or zero scored cooks (real competition 4) | mitigate | `buildComparisonTable` and its aggregate helpers are empty-set safe; the zero-cook case short-circuits to a copy block before the table renders |
| T-10-SC | Tampering | npm installs | accept | No package-manager installs in this phase (RESEARCH.md Package Legitimacy Audit: not applicable) |
</threat_model>
