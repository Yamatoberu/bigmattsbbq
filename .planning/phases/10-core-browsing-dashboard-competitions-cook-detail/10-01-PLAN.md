  <action>
Create `lib/sca/format.ts` (pure, no `server-only`, no external deps) exporting `EM_DASH`, `formatScoreValue`, `cookColumnLabel`, `formatEventDate`, `formatCookDate`.

`formatScoreValue(value: number | null | undefined): string` — returns `EM_DASH` when the value is `null`, `undefined`, or fails `Number.isFinite`; otherwise rounds to at most 2 decimal places and strips trailing zeros (`Number(value.toFixed(2)).toString()`).

`cookColumnLabel(competitionName: string | null | undefined, steakLabel: string | null | undefined): string` — implements the DASH-02 formula verified against real data in RESEARCH.md Pattern 4: both present → `` `${competitionName} - ${steakLabel}` ``; only name → name; only label → label; neither → the literal `"Untitled Cook"`. Treat whitespace-only strings as absent.

`formatEventDate(dateOnly: string): string` — for `competition.event_date`, which is a Postgres DATE serialized as `"YYYY-MM-DD"`. Use `Intl.DateTimeFormat("en-US", { month: "short", day: "numeric", year: "numeric", timeZone: "UTC" })`. The `timeZone: "UTC"` is load-bearing: `new Date("2025-11-01")` parses as UTC midnight, and formatting that in `America/Denver` would render `Oct 31, 2025`. Do not reuse `formatDenverDateTime` for this field.

`formatCookDate(isoTimestamp: string): string` — for `cook.cooked_at`, a real timestamptz. Use `Intl.DateTimeFormat("en-US", { month: "short", day: "numeric", year: "numeric", timeZone: "America/Denver" })`, matching the existing `lib/format.ts` timezone convention but omitting the time-of-day parts.

Then create `tests/sca-format.test.ts` covering every case listed in `<behavior>` above, structured like `tests/sca-scoring.test.ts` (`import { describe, expect, it } from "vitest";`, one `describe` per exported function).
