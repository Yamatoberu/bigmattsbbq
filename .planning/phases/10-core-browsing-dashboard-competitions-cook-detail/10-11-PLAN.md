<objective>
Close gap G-10-2: `app/sca/competitions/[id]/page.tsx` calls `buildComparisonTable(competition.cook, { aggregates: true })`, so Worst Cook / Best Cook / Cook Averages are derived from that competition's own cooks. For a single-cook competition — the common case in live data (competition 4) — those three columns are identical to the single cook's own column, which is redundant and uninformative.

Purpose: COMP-03 asks for a side-by-side comparison on competition detail. The developer's UAT verdict is that the comparison must be against the chef's overall/rolling aggregate across all recorded cooks — the same source the Dashboard's Cook Averages column uses — not a recomputation scoped to the event.
Output: `buildComparisonTable` gains a separable aggregate source and an optional scope label; competition detail passes the global cook set; the Dashboard's behavior is unchanged.
</objective>
