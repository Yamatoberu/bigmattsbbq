## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| `GET /api/attribution-sources` response → React render | Server-supplied `label` strings are rendered as option text in the browser |
| checkout form → `POST /api/checkout` | Customer-typed `attributionDetail` free text leaves the browser |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-12-08 | Tampering | `source.label` rendered as `<option>` text in `CheckoutClient.tsx` | mitigate | Labels are rendered as JSX text children, which React auto-escapes. No `dangerouslySetInnerHTML` anywhere in this component — enforced by the repo-wide absence of that API and by review of this diff. The values originate from an admin-controlled Supabase config table, not from user input. |
| T-12-09 | Denial of Service | `attributionDetail` free-text input | mitigate | `maxLength={255}` on the input mirrors the server's Zod `.max(255)`, so the normal path never produces a payload the server would 400. The client bound is convenience only; the authoritative bound is plan 03's Zod schema plus `buildAttributionMetadata()`'s truncation. |
| T-12-10 | Denial of Service | attribution fetch failure blocking checkout | mitigate | D-09 render gate (`!attributionSourcesError && attributionSources.length > 0`) hides the question entirely, and the hook's `isLoading` is deliberately NOT destructured so it cannot enter the submit button's `disabled` expression. A `/api/attribution-sources` outage therefore cannot prevent a sale. Enforced by the `disabled` source assertion above. |
| T-12-05 | Elevation of Privilege | service-role Supabase key reaching the browser | mitigate | Neither new client file imports `lib/supabase.ts` or `lib/attributionSources.ts`; the browser reaches the data only through the API route. Enforced by the `grep -c "lib/supabase\|lib/attributionSources\|server-only"` returns-0 criterion in Task 1. |
| T-12-SC | Tampering | npm installs | accept | No new packages installed in this phase (12-RESEARCH.md "Package Legitimacy Audit: N/A"). |
