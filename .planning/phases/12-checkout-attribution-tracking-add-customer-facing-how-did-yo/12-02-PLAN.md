<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → `GET /api/attribution-sources` | Unauthenticated public endpoint; response is served to any visitor of `/checkout` |
| API route → Supabase (service-role key) | The route uses a key that bypasses RLS; the query must therefore self-restrict to the public-safe subset |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-12-03 | Information Disclosure | `GET /api/attribution-sources` error path | mitigate | Catch block returns the fixed string `"Unable to load attribution sources."` plus a `requestId`; the raw Supabase/PostgREST error goes only to `logError`. Asserted by a test that the 500 body contains no `PGRST301` substring. Mirrors `app/api/frozen-items/route.ts`. |
| T-12-04 | Information Disclosure | `fetchActiveAttributionSources()` column selection | mitigate | Explicit `.select("id, code, label, sort_order, requires_detail")` and `.eq("is_active", true)` rather than `select("*")`, so `created_at`/`updated_at` and any future internal column are never exposed through a service-role-key query that bypasses RLS. |
| T-12-05 | Elevation of Privilege | service-role Supabase key reaching the browser | mitigate | `lib/attributionSources.ts` begins with `import "server-only"`, which makes any client-component import a build-time error. The browser reaches this data only through the API route. Enforced by the `head -1` acceptance criterion. |
| T-12-SC | Tampering | npm installs | accept | No new packages installed in this phase (12-RESEARCH.md "Package Legitimacy Audit: N/A"). |
