  <action>
    Create `components/sca/TrendChart.tsx` exporting a named `TrendChart` function component (no default export, no `"use client"` — this must stay a Server Component per D-02; it uses no hooks, no event handlers).

    Props: `title: string`, `points: TrendPoint[]`, `accent: "ember" | "gold"`. Import `TrendPoint` as a type-only import from `../../lib/sca/trends` and `formatScoreValue` from `../../lib/sca/format`.

    Card wrapper: `<div className="glass-card p-6">` containing the title as `<p className="text-xs font-semibold uppercase tracking-[0.25em] text-smoke-800">`, then the chart, then a caption `<p className="mt-3 text-sm text-smoke-800">`. Declare the repeated class strings as module-level constants the way `SummaryCards.tsx` does.

    Three render branches, checked BEFORE any min/max scaling math (RESEARCH.md Pitfall 2 — `min`/`max` on an empty array, and `max - min === 0`, both break the scale):
    - `points.length === 0`: render no `<svg>` at all; caption text is exactly `No cooks recorded yet.`
    - `points.length === 1`: render the `<svg>` with a single `<circle>` at the horizontal and vertical center of the plot band and NO `<polyline>`; caption text is exactly `Not enough data yet.`
    - otherwise: full chart; caption text is `{points.length} cooks · latest {formatScoreValue(last.value)}` using the middle-dot separator.

    SVG canvas: `viewBox="0 0 600 160"`, `className="mt-4 w-full"`, `role="img"`, and an `aria-label` reading `{title} trend: {points.length} cooks from {first.label} to {last.label}, latest {formatScoreValue(last.value)}`. Do not set a fixed pixel `height` attribute — viewBox plus `w-full` is what makes it responsive with zero JS.

    Plot geometry (viewBox units, exempt from the 8-point spacing scale): x spans 16 to 584 (568 wide), y spans 28 to 132 (104 tall). X position is index-spaced: `16 + (index / (points.length - 1)) * 568`. Y position is a linear scale over the series' own `[min, max]` expanded by 10% of the range on both ends, inverted for SVG's top-down axis, mapped into the 28–132 band. When the expanded range would still be zero (all values identical), place every point at the vertical center of the band rather than dividing by zero.

    Each chart scales to its OWN min/max. Never compute or accept a shared y-domain across charts — category scores top out near 50 while total score tops out near 254.5, and a shared scale flattens the category charts.

    Line and markers: one `<polyline>` with `fill="none"`, `strokeWidth="2"`, `strokeLinecap="round"`, `strokeLinejoin="round"`; one `<circle r="3">` per point with a solid fill and no stroke. Both stroke and fill use `#ff5f3b` when `accent` is `"ember"` and `#d8b56a` when `accent` is `"gold"` — resolve this through a single module-level lookup so the hex literals appear once each.

    Value labels: render a `<text>` only at the first point, the last point, and the point(s) achieving the series min and max, deduped by index so one point never gets two overlapping labels. Text is `formatScoreValue(point.value)`, `fill="#f7f1e6"`, `fontSize="12"`, `textAnchor="middle"`, positioned with `dy="-8"` by default and flipped to `dy="14"` when the point's y falls in the top 20% of the plot band (y below 28 + 0.2 * 104) so labels are never clipped at the viewBox edge.

    Date labels: only the first and last point, rendered at `y="152"`; first point with `x="16"` and `textAnchor="start"`, last point with `x="584"` and `textAnchor="end"`. Text is `point.label` (already formatted by `buildTrendSeries` — do NOT call `toLocaleDateString` or re-derive a date string here). `fill="#e8ddd1"`, `fontSize="11"`.

    Keep all geometry helpers module-private. No `any`, no non-null assertions, no JSDoc or inline comments, 2-space indent, final newline.
