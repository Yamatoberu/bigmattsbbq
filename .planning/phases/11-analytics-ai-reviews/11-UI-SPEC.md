# Phase 11 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

This phase belongs to the **SCA Tracker** sub-app (`app/sca/`, `components/sca/`, `lib/sca/`) — a design system distinct from the main storefront (root `CLAUDE.md`) but 100% reusing the site's existing hand-rolled Tailwind theme. No new visual system, no new component library, no new dependency is introduced by this phase (locked by INFRA-04 and CONTEXT.md D-01's rationale). All values below are pre-populated from the existing `app/sca/*` codebase (Phase 9/10 precedent) and CONTEXT.md's locked decisions — nothing in this contract is new visual language.

## Component Specification: `TrendChart`

Server Component, static inline SVG, zero client JS, per D-01/D-02. One shared component parameterized by `title`/`points`, rendered up to 7 times on `/sca/analytics` (Total Score, Gap to First, and 5 judging categories).

**Card wrapper** (matches `SummaryCards`' card idiom exactly):
```
<div className="glass-card p-6">
  <p className="text-xs font-semibold uppercase tracking-[0.25em] text-smoke-800">{title}</p>
  <svg viewBox="0 0 600 160" role="img" aria-label={...} className="mt-4 w-full">...</svg>
  <p className="mt-3 text-sm text-smoke-800">{caption}</p>
</div>
```

**SVG canvas:**
- `viewBox="0 0 600 160"`, `width="100%"`, no fixed pixel `height` attribute — this is what makes the chart responsive/mobile-first with zero JS.
- Plot bounds inside the viewBox: `x` from 16 to 584 (568 wide), `y` from 28 to 132 (104 tall). The 28px top margin reserves room for min/max/first/last value labels above the topmost point; the 28px bottom margin reserves room for first/last date labels below the plot.

**Scaling:**
- X position: index-spaced, `x = 16 + (index / (n - 1)) * 568` for `n > 1`. Cooks are not evenly spaced in real time; index-spacing avoids empty/crowded regions and is the standard small-multiple simplification.
- Y position: linear scale over `[seriesMin, seriesMax]` expanded by 10% of range on both ends, inverted for SVG's top-down axis, mapped into the 28–132 plot band.
- **Each of the 7 charts scales independently.** Never share one y-domain across charts — category scores (~0–50) and total score (~0–254.5) on a shared scale would flatten the category charts to near-invisible lines.

**Line + points:**
- `<polyline>`: `strokeWidth="2"`, `fill="none"`, `strokeLinecap="round"`, `strokeLinejoin="round"`.
- One `<circle r="3">` per point, filled solid (no stroke ring).
- Color: Total Score and Gap-to-First charts use `ember-400` (`#ff5f3b`) for both polyline stroke and circle fill. The 5 category charts use `gold-400` (`#d8b56a`) for both. (See Color contract above — this is the only new accent usage this phase adds.)

**Labels (no hover exists, so labels are baked into the static render — D-02):**
- Value labels: shown only at the first point, last point, and the point(s) achieving the series min/max (dedupe if one point serves multiple roles) — not every point, to avoid clutter on a 21-point mobile-width chart. Text = `formatScoreValue(point.value)`, `fill-[#f7f1e6]`, font-size 12px, positioned 8px above the point (`dy="-8"`) by default, flipped to 14px below (`dy="14"`) when the point sits in the top 20% of the plot band (to avoid clipping above the viewBox edge).
- Date labels: only the first and last point get a date label, rendered at the bottom of the canvas (`y="152"`) — first point left-aligned (`text-anchor="start"`, `x="16"`), last point right-aligned (`text-anchor="end"`, `x="584"`). Text = `formatCookDate(point.date)` (America/Denver, matches every other cook-date display in `app/sca`). `fill-smoke-800`, font-size 11px.

**Accessibility (mandatory since there is no hover/tooltip):**
- `<svg role="img" aria-label="{title} trend: {n} cooks from {first.label} to {last.label}, latest {formatScoreValue(last.value)}">` — the text alternative must be baked in, not added later.

**Caption** (below the SVG, `mt-3 text-sm text-smoke-800`):
- Standard: `"{points.length} cooks · latest {formatScoreValue(last.value)}"`.
- Empty (`points.length === 0`): render the existing empty-card idiom instead of an SVG — `<p className="text-sm text-smoke-800">No cooks recorded yet.</p>` with no `<svg>` element at all.
- Single point (`points.length === 1`): render one static `<circle>` at the horizontal/vertical center of the plot band, no `<polyline>` (a 1-point polyline draws nothing useful), caption reads `"Not enough data yet."`.

## Page Layout: `/sca/analytics`

Mirrors the existing page shell exactly (`section-spacing` wrapper, h1/subtitle pattern from `cooks/page.tsx`):

```
<div className="section-spacing">

  <div className="mt-8">
    <h2 className="font-[var(--font-display)] text-2xl font-semibold text-[#f7f1e6]">Score & Gap to First</h2>
    <div className="mt-4 grid gap-4 sm:grid-cols-2">
      <TrendChart title="Total Score" .../>   {/* ANLY-01 */}
      <TrendChart title="Gap to First" .../>  {/* ANLY-02 */}
    </div>
  </div>

  <div className="mt-8">
    <h2 className="font-[var(--font-display)] text-2xl font-semibold text-[#f7f1e6]">Judging Categories</h2>
    <div className="mt-4 grid gap-4 sm:grid-cols-2 lg:grid-cols-3">
      <TrendChart title="Appearance" .../>
      <TrendChart title="Doneness" .../>
      <TrendChart title="Texture" .../>
```

- Mobile-first: both grids are single-column below the `sm` breakpoint (one chart per row, full width) — this is the default per D-05's rationale (five overlapping lines / a wide multi-line chart is unreadable at phone width; stacked single-column small multiples scan cleanly).

- Category order is fixed: Appearance, Doneness, Texture, Taste, Overall Impression — matches the existing field order in `buildScoreRows()` (`app/sca/cooks/[id]/page.tsx`), so the same category sequence appears consistently across Cook Detail and Analytics.
- Error state: identical single `glass-card` + generic message pattern used by every other `app/sca` route (see Copywriting Contract).

## Page Layout: `/sca/ai-reviews` (list)

Mirrors `app/sca/cooks/page.tsx` structurally (h1/subtitle, `space-y-4` list of `glass-card` rows, identical empty/error states):

```
<div className="section-spacing">
  <h1 className="font-[var(--font-display)] text-4xl font-semibold text-[#f7f1e6]">AI Reviews</h1>
  <p className="mt-2 max-w-2xl text-sm text-smoke-800">Every AI review Big Matt's cooks have received, newest first.</p>

  {/* error or empty state uses the exact glass-card idiom from cooks/page.tsx */}

  <div className="mt-8 space-y-4">
    {reviews.map((review) => (
      <div key={review.id} className="glass-card p-6">
        <div className="flex flex-wrap items-center gap-3">
          <span className="badge">{review.review_type ?? EM_DASH}</span>
          <span className="text-xs uppercase tracking-[0.25em] text-smoke-800">{review.model ?? EM_DASH}</span>
          <span className="text-xs uppercase tracking-[0.25em] text-smoke-800">{formatCookDate(review.created_at)}</span>
        </div>

        <Link href={`/sca/cooks/${review.cook?.id}`} className="mt-3 min-h-[44px] inline-flex items-center text-smoke-800 hover:text-gold-300 ...">
          {cookColumnLabel(review.cook?.competition?.name ?? null, review.cook?.steak_label ?? null)}
        </Link>

        <p className="mt-3 line-clamp-3 text-sm text-[#f7f1e6]">{review.comments}</p>

        <Link href={`/sca/ai-reviews/${review.id}`} className="mt-4 min-h-[44px] inline-flex items-center text-smoke-800 hover:text-gold-300 ...">
          Read Full Review
        </Link>
      </div>
    ))}
  </div>
</div>
```

- **Badge:** `review_type` renders using the existing `.badge` class verbatim (rounded-full, ember-red background `#7a1a0e`, `0.66rem` uppercase tracking-`[0.35em]` text) — the same visual weight as any other status badge, falling back to `EM_DASH` when `review_type` is `null` (D-03).
- **Model + date:** rendered as plain label-style text (`text-xs uppercase tracking-[0.25em] text-smoke-800`), not badges — only `review_type` gets the pill treatment, keeping one badge per row so the eye has a single scan anchor.
- **Cook + competition inline:** the cook's `cookColumnLabel()` string (which already folds the competition name into itself, e.g. `"Fall Throwdown - Wurst A"`) is itself a clickable link to `/sca/cooks/:id` (D-06's "linked cook + competition inline" + resolves RESEARCH.md's Open Question #2: yes, make it a link).
- **Comments preview:** `line-clamp-3` (Tailwind 3.4's built-in line-clamp utility, no plugin needed) truncates the full comment to 3 lines on the list row; the detail page (below) shows the untruncated text.
- **CTA:** "Read Full Review" links to `/sca/ai-reviews/:id`, styled with the same `LINK_CLASSES` pattern as "View Cook" elsewhere in the app.
- **Empty state:** `glass-card mt-8 p-6` containing `<h2>No AI reviews recorded yet.</h2>` + `<p>Check back after Big Matt's next AI review run.</p>` — matches the exact heading/body-copy structure of `cooks/page.tsx`'s empty state.
- **Sort order:** list is pre-sorted `created_at` desc by the query itself (`getAllAiReviews()`); no client-side re-sort in the page component (D-06).

## Page Layout: `/sca/ai-reviews/[id]` (detail)

Mirrors `app/sca/cooks/[id]/page.tsx` structurally (h1/subtitle-with-links, `glass-card` content sections, back-navigation footer):

```
<div className="section-spacing">
  <h1 className="font-[var(--font-display)] text-4xl font-semibold text-[#f7f1e6]">{review.model ?? EM_DASH}</h1>
  <p className="mt-2 text-sm text-smoke-800">
    <span className="badge">{review.review_type ?? EM_DASH}</span>
    {" · "}{formatCookDate(review.created_at)}
    {review.cook && (
      <>
        {" · "}
        <Link href={`/sca/cooks/${review.cook.id}`} className="hover:text-gold-300 ...">
          {cookColumnLabel(review.cook.competition?.name ?? null, review.cook.steak_label)}
        </Link>
        {review.cook.competition && <> · {formatEventDate(review.cook.competition.event_date)}</>}
      </>
    )}
  </p>

  <div className="mt-8">
    <h2 className="font-[var(--font-display)] text-2xl font-semibold text-[#f7f1e6]">Comments</h2>
    <div className="glass-card mt-4 p-6">
      <p className="whitespace-pre-line text-sm text-[#f7f1e6]">{review.comments}</p>
    </div>
  </div>

  {review.prompt && (
    <div className="mt-8">
      <h2 className="font-[var(--font-display)] text-2xl font-semibold text-[#f7f1e6]">Prompt</h2>
      <div className="glass-card mt-4 p-6">
        <p className="whitespace-pre-line text-sm text-[#f7f1e6]">{review.prompt}</p>
      </div>
    </div>
  )}

  <div className="mt-8 flex flex-wrap gap-6">
    <Link href="/sca/ai-reviews" className="min-h-[44px] inline-flex items-center text-smoke-800 hover:text-gold-300 ...">Back to AI Reviews</Link>
    {review.cook && (
      <Link href={`/sca/cooks/${review.cook.id}`} className="min-h-[44px] inline-flex items-center text-smoke-800 hover:text-gold-300 ...">View Cook</Link>
    )}
  </div>
</div>
```

- **h1 identity:** `review.model` (falls back to `EM_DASH` — a review with no model is unusual but not impossible per the nullable schema; the badge/date/cook subtitle still carries meaning even if the model name is missing).
- **Subtitle composition:** `review_type` badge + created-at date + (if `review.cook` present) a link to the cook using `cookColumnLabel()` + event date — this exactly mirrors Cook Detail's own subtitle pattern (`formatCookDate` + competition link + `formatEventDate`), so the two detail pages read as siblings.
- **Prompt section: rendered only when `review.prompt` is non-null** — no "Prompt: —" placeholder, no empty section, per D-04. When null, the section (heading and card) does not exist in the DOM at all.
- **Comments section:** always rendered (comments is `NOT NULL` in the schema), full untruncated text with `whitespace-pre-line` to preserve the AI model's paragraph breaks — same treatment already proven on Cook Detail's inline AI review rendering.
- **Defensive null-cook handling (Pitfall 3):** `review.cook` is typed nullable despite the FK guarantee (matches the existing codebase convention of never trusting embed nullability away). When `null`, the cook/competition portion of the subtitle and the "View Cook" back-link are both omitted — no broken link, no `cook!` non-null assertion.
- **Error/not-found states:** identical to Cook Detail — `parseScaId()` + `notFound()` for an invalid `[id]`, `PGRST116` → `null` → `notFound()` for a missing row, `try/catch` + `logError()` + the generic error string for any other failure.
